# AGENTS.md

Personal blog at [aymeric.fyi](https://aymeric.fyi). Next.js 15 (App Router) + Contentlayer2 + Tailwind 4, based on the `tailwind-nextjs-starter-blog` template.

## Creating a new blog post

**This is the most common task in this repo. Everything you need is below — no need to explore first.**

1. Create `data/blog/<slug>.mdx`. The filename is the URL slug: `data/blog/my-post.mdx` → `/blog/my-post`. Use **kebab-case**.
2. Add frontmatter (see schema below).
3. Write the body in MDX.
4. If the post has images, put them in `public/static/images/<post_topic>/` and reference them as `/static/images/<post_topic>/file.png`.

That's it. No index to update, no registry to touch — Contentlayer picks up any `.mdx` under `data/blog/**` automatically. `app/tag-data.json` and the search index are **generated** at build time; never edit them by hand.

### Frontmatter

Defined in `contentlayer.config.ts` (the `Blog` document type). Only `title` and `date` are required.

```yaml
---
title: 'Post Title'                    # required
date: '2026-08-11'                     # required, YYYY-MM-DD
tags: ['AI', 'Software Engineering']   # human-readable; slugified for URLs
draft: false                           # true hides it from production builds
summary: 'One or two sentences. Used on the post list and in meta description.'
images: ['/static/images/topic/hero.png']  # images[0] is the social/OG image
---
```

Other supported fields: `lastmod`, `authors` (defaults to `data/authors/default.mdx`), `layout`, `bibliography`, `canonicalUrl`, `url`.

Existing tags (reuse these rather than inventing near-duplicates): `AI`, `Software Engineering`, `Mobile Development`, `Engineering Management`, `Design`, `Mercari`, `Process`.

### Body conventions

For tone and structure, follow `data/blog/building-ontrack.mdx` (first-person experience report, hero image, few headings) and `data/blog/gemini-pricing-increase-202604.mdx` (argument-driven, numbers-heavy, builds to a conclusion).

- Start at `##` — `#` is reserved for the title, which the layout renders from frontmatter.
- If the post opens with a hero image, put the `![alt](/static/images/...)` right after the frontmatter.
- Long posts use a hand-written "## Table of Contents" with anchor links (`- [Section](#section)`). Anchors are GitHub-style slugs of the heading.
- Escape `$` as `\$` when writing prices — `remark-math` is enabled and will otherwise try to parse it as math.
- GFM is on: tables, strikethrough, task lists all work. GitHub-style alerts (`> [!NOTE]`) work too.
- Code blocks support titles: ` ```js:filename.js `.

### MDX components available in post bodies

From `components/MDXComponents.tsx`: `<Image>`, `<TOCInline>`, `<BlogNewsletterForm>`. Links, `<pre>`, and `<table>` are auto-wrapped, so plain markdown is fine for those.

### Layouts

`layout` in frontmatter picks the post layout; the default is `PostLayout` (with author sidebar). Alternatives: `PostSimple`, `PostBanner`. All live in `layouts/`.

## Repo layout

| Path | What's there |
| --- | --- |
| `data/blog/` | Blog posts (`.mdx`) — the content source |
| `data/authors/` | Author profiles; `default.mdx` is the fallback author |
| `data/siteMetadata.js` | Site title, URL, social links, analytics, comments, search config |
| `data/projectsData.ts` | Cards on the `/projects` page |
| `data/headerNavLinks.ts` | Top navigation |
| `data/references-data.bib` | BibTeX for `rehype-citation` |
| `public/static/images/` | Post images, one subfolder per post/topic |
| `app/` | Next.js App Router pages |
| `layouts/` | Post and list layouts |
| `components/` | Shared React components |
| `css/` | Tailwind and Prism theme |

## Commands

```bash
yarn dev      # local dev server
yarn build    # production build + postbuild (RSS, sitemap)
yarn lint     # eslint --fix over app, components, layouts, scripts
```

Husky + lint-staged run Prettier and ESLint on commit.

## Notes

- `app/tag-data.json` and `public/search.json` are build artifacts. They are regenerated by `contentlayer.config.ts` `onSuccess`. Do not hand-edit.
- Content lives in `data/`, not `content/` — `contentDirPath` is `data`.
- Filenames are inconsistent historically (one post uses snake_case). Use kebab-case for anything new.
